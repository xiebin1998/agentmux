AgentMux 架构说明

桌面客户端 · Rust + Tauri v2 · React + TypeScript · 更新于 2026-09-19

把「IM 里有人 @我 → 交给本机 AI Agent 处理 → 把回复发回原会话」从一次性脚本， 做成常驻、可插拔、带界面的桌面客户端。

一、分层与进程拓扑

界面层 React + TS 三栏布局：项目/会话树 · 视图区 · 上下文面板 通过 invoke 调命令，监听层用 Tauri Channel 推流
宿主层 Rust 进程 Orchestrator 监听生命周期 · 回复引擎 · 存储 · 配置 · 托盘 所有持久化与子进程都发生在这一层
外部 CLI 子进程 dws（钉钉事件与发送） · Agent CLI（Qoder/Claude/Codex） 全部 CREATE_NO_WINDOW，stdin/stdout/stderr 走管道
外部服务 钉钉开放平台（长连接订阅） 由 dws 进程持有，宿主不直接联网

二、模块职责

模块职责关键点
main.rs状态装配、命令注册、托盘、关闭拦截点 × 时 prevent_close + 发 close-requested 事件交前端询问
resolve.rs平台注册表 + CLI 自动解析按命令名走 PATH 探测版本/登录态；另解析出真实可启动路径供 spawn
orchestrator/监听生命周期spawn → ready 门控(30s) → 退避(5/10/20/40/60s) → 停机阶梯 → 全局去重
reply.rs回复引擎prompt 走 stdin；剔除 @、压平空白、按字符截断；会话参数追加在参数末尾
storage/SQLite + ndjson 归档事件/会话/摘要；启动时幂等迁移旧库
config/全局设置 + 设置解析reply_settings_for_project：项目优先、全局兜底
project.rs项目模型与存储工作目录 / CLI / 回复设置 / 平台选择
process.rs子进程工具统一隐藏控制台窗口
providers/提供方检测DetectReport 区分「未安装」与「已安装未登录」

三、两条关键数据流

3.1 监听链路

  1. 界面在某个项目里点「@我」或「单聊」→ start_listener(project_id, kind, settings, channel)
  2. 宿主解析 IM CLI 路径（必要时按平台自动解析），spawn dws event +listen-im --kind <k>
  3. stderr 出现 [event] ready … 才算就绪；30s 未就绪判定失败并退避重试
  4. stdout 的 NDJSON 逐行解析 → 打上 project_id → 全局去重 → 落盘 → 推流到界面
  5. 退出：关 stdin 等 10s → 未退则按 pid taskkill /T /F；退订按 subscribe_id 精准执行

3.2 回复链路

  1. 判定：畸形事件/无会话 → 跳过；发送者等于自身身份 → 跳过；其余继续（裸 @ 不跳过，用占位问句）
  2. 全局串行（一次只处理一条）
  3. 按需自动压缩上下文
  4. 拼 prompt：会话摘要 + 最近若干条消息（受条数与字符预算约束）
  5. 取会话：按 (project_id, conversation_id) 建档，首次 --session-id，之后 --resume
  6. 调 Agent CLI 生成（工作目录 = 项目的 work_dir，只读工具白名单，超时可配）
  7. 清洗正文（剔除 @、压平空白、按字符截断）
  8. 经 dws chat +messages-send 发回原会话，幂等键取原 message_id
  9. 台账写 sent / failed（失败保留原文）

旧库启动时按列存在性做幂等迁移；sessions 从「会话单列唯一」重建为「项目 + 会话」复合键。

五、扩展缝

IMImProvider —— id / supported_kinds / detect / start_listen / fetch_history / send_message

AgentAgentProvider —— id / supports_session_resume / detect / generate

平台resolve::PLATFORMS —— 新增一个 IM 或 Agent 平台 = 注册表加一行 （id / display / kind / commands / fallbacks / version_args），界面单选会自动出现。

DetectReport 必须区分「未安装」与「已安装未登录」（logged_in / not_logged_in / unknown，unknown 专表示探测失败）。

六、关键设计决策与原因

决策原因（多为实测结论）
监听、回复设置、工作目录按项目隔离全局单例做不到「项目下挂会话 / 每项目独立开关 / 用项目工作目录」
CLI 按命令名探测，另存可启动路径界面不该暴露目录；但 Windows 上 PATH 里的 dws 是脚本、dws.cmd 是包装脚本，不带 shell 无法直接 spawn，启动这一步仍需真实可执行文件
不 spawn .ps1 与无扩展名脚本实测：cmd /C x.ps1 不执行而是用文件关联打开（会弹编辑器）
子进程统一 CREATE_NO_WINDOW否则 Windows 上每次 spawn 都建控制台窗口，轮询时表现为「黑框一直闪」
提供方检测不轮询检测会 spawn 进程，属显式动作、结果不缓存；程序启动时**只检测一次**，之后由界面上的 ⟳ 手动触发（用 ref 守卫避免 StrictMode 双跑）
Agent 子进程 env_remove SDK 变量实测：宿主若带 QODER_AGENT_SDK_ENTRYPOINT，CLI 会被推入 SDK 模式并直接报 sdk_invalid_args
停机阶梯 + 精准退订关 stdin 优雅退出为优先；退订绝不 event stop --all，避免误伤其它订阅
裸 @ 不跳过对方只 @ 一下时直接跳过，用户看到的是「收到消息但没回复」
会话列表过滤空 conversation_id畸形事件会形成一条点了没反应的「空会话」，出现在左树里
配置和数据同放一个可迁移的数据目录安装到非系统盘或迁移数据时，配置不能掉队；%APPDATA%\agentmux\location.json 只当「指针」，永远留在系统盘负责找到当前数据目录
压缩阈值用百分比而非字符数字符上限是每个项目各自配的，让用户直接填两个数字既难换算也易错；改由「上下文占用百分比」换算
身份按 IM 平台分别存IM 不只有钉钉：跨平台的「全局身份」没有语义，im_identities[platform_id] 才能随新平台扩展
不提供旧数据导入，改为会话归类导入要维护一整套旧 schema 解析；历史会话用 assign_conversation 在左树「未归类」里归入项目即可

八、已知限制与待决项

限制

  • 外部 manifest 插件本版不提供，只有内置适配器
  • 改回复设置需重启该项目的监听才生效
  • 升级前的历史事件 project_id 为空，不会挂在项目下；在左树「未归类（历史会话）」里可将其归入指定项目

待决（需长期观察或实际使用）

编号问题为什么现在不拍板
D-23单聊 conversation_id 形态需从另一账号发单聊消息验证
D-33断连重连 vs 保活实测 bus 空闲 300s 会断，但保活是否有意义需长期观察
D-59压缩触发阈值需记录长度与回答质量的关系，不能拍脑袋
D-75关闭上下文对回答质量的影响需长期使用对比
D-76哪些改动需要重启实现期逐项确认，界面已如实标注

九、常用命令

# 开发
cargo tauri dev                       # 起 Vite + 编译 + 开窗口

# 校验
